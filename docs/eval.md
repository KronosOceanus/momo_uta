# 评测集与基线

> 服务设计见 [`yomi.md`](yomi.md)；开发笔记见 [`NOTES.md`](NOTES.md)。

给「日语标注服务」（振假名 / 罗马音 / 键盘键位）准备的评测底座。

**为什么先做评测**：服务的核心约束是"不设人工复核"——那 precision 就必须可度量，
否则每次改规则都只能靠感觉。这份文档说明**评什么、怎么算、现在多少、哪里不可信**。

设计（判定链、档位、契约）在 [`yomi.md`](yomi.md)；
踩过的坑和决策记录在 [`NOTES.md`](NOTES.md)。

## 数据来源与许可

| 来源 | 用途 | 许可 |
|---|---|---|
| [青空文庫](https://www.aozora.gr.jp/) ruby 付きテキスト | 散文域 | 作品为公有领域；注記形式公开 |
| [Uta-Net](https://utaten.com/) 动漫榜歌词页 | 歌词域（J-Pop / 动漫歌） | 页面自带人工振假名；**个人工具使用，数据只落本地缓存，不进发行物** |
| 青空文庫 全作品索引 CSV | 作品元数据、`文字遣い種別` 过滤 | 同上 |
| 手工构造（`eval/manual.jsonl`） | 稀有规则的边界样例 | 本项目 |

歌词域直接用现代 J-Pop / 动漫歌：`utaten.com/ranking/anime/` 的榜单页给出 lyric 链接，
歌词页里每个汉字词都是人工标注的 `<span class="ruby"><span class="rb">素直</span><span class="rt">すなお</span></span>`，
等于免费拿到 gold。同页还有官方罗马音（`romaji_official`），可以顺带校验转写层。

缓存位于 `data/sources/lyrics/`，已在 `.gitignore` 里；这份数据只用于本地评测。

## 评测集构成

### 分层（散文域）

按本文 §分层规则 的配额抽样，每条记录带 `rules` 与 `primary`：

```text
R1  基线（含未命中特殊规则的句子） 260
R3  音便（促音・連濁）              80
R4  熟字訓                          60
R5  多音詞                          80
R6  数字 + 助数詞                    60
R7  固有名詞                        60
R8  当て字・造語                    40
R9  假名直通（K 级）                100
R10 片假名外来語                    60
R11 拉丁/数字混在                   60

R2（送り仮名）与 R12（熟語切分）只作标签，不单设层——它们对几乎每句都成立。
```

抽样是**确定性**的（固定 seed），同一版本可复现；每层独立配额，避免高频词淹没稀有规则。

### 歌词域

`utaten.com/ranking/anime/` 前 30 首，每首最多 80 行（约 1300 行）：

```text
来源   Uta-Net 歌词页，振假名由站点人工标注（rb/rt 结构）
字段   title / artist / url / text / spans / romaji_official / domain="lyrics"
```

`eval/reports/lyrics_coverage.md` 是自动生成的**曲 × 规则**矩阵：每格是该曲命中该规则的行数，
用来回答"这部分歌词覆盖了哪些规则"，也能立刻看出哪条规则在歌词域是空白。

### 手工边界集

`eval/manual.jsonl` 补青空文庫里稀有的情况：数字+助数詞、固有名詞、当て字、拉丁混排、多音词。

## 怎么跑

```bash
# 0) 一次性：装依赖 + 建词典表
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python tools/build_tables.py && .venv/bin/python tools/fetch_jpop.py --resource

# 1) 构建散文域 gold（首次会下载作品，之后走 data/sources 缓存）
.venv/bin/python tools/build_gold.py --works 40

# 2) 构建歌词域 gold
.venv/bin/python tools/fetch_jpop.py

# 3) 验证管线
make eval-dummy

# 4) 真实评测 / 留出集 / 泛化集 / 弃权
make eval-real     # 开发集
make eval-test     # 留出集（对外报这个）
make eval-gen      # 泛化集（动漫榜 + 综合榜 + 实时榜 + V家榜）
make ceiling       # 表覆盖率（不是上限）
make stats         # 全量统计（与 eval 同口径）
make tables-check  # 打印各表条目数（缺表会报错）
make build-stats   # 重算出语料读音分布表
make audit-patches # 人工补丁赚亏

# 5) 生成演示页
.venv/bin/python tools/render.py --pair demo/src/gunjou.txt --title 群青
```

单句标注、响应契约、版本字段见 [`yomi.md`](yomi.md) §5.4：

```bash
.venv/bin/python tools/annotate.py --text "大人と子供"     # 单句 JSON
echo '{"text":"大人"}' | .venv/bin/python tools/annotate.py --stdio   # stdio 协议
```

## 当前基线（2026-11）

| 数据集 | 曲/条 | span | 只算日文 | precision | coverage |
|---|---|---|---|---|---|
| 歌词开发集 | 30 首 | 3524 | 3372 | **95.2%** | **94.4%** |
| 歌词留出集 | 20 首 | 2377 | 2324 | **94.9%** | **93.3%** |
| 歌词泛化集 | 27 首 | 3038 | 3035 | **94.5%** | **94.0%** |
| 散文域 | 742 条 | 1173 | 1173 | **74.9%** | **73.4%** |

（precision / coverage 是 `--exclude-latin` 口径，即"只算日文 span"）

散文域是"难词子集"口径：Aozora 编者只标难词（1.6 处/行），我们标 10 处/行。

### 按档位的结果

判定规则、档位定义、LLM 的角色都在 [`yomi.md`](yomi.md) §3。
这里只放结果（歌词开发集）：

| 档 | span | precision | 含义 |
|---|---|---|---|
| A | 7415 | 96.2% | 语料证明单读 / 人工确认 |
| AB | 1200 | 91.7% | 多读，但读音是语料主读 |
| B | 904 | 73.4% | 多读≠主读 / 专名 / 数字 |
| C | 237 | — | OOV / 对齐失败（弃权） |

### 政策层（`--emit`）

只决定"输出到哪一档"，不改判定。这也是**精度–覆盖率曲线**：

```text
emit=B   全出      开发 95.2 / 94.4
emit=AB  只出 A/AB  开发 95.7 / 87.2
emit=A   只出 A     开发 95.2 / 73.8
```

曲线几乎平：隐藏一档会同时删掉对的和错的，**不是"更谨慎"，只是"更少"**。

### LLM（`--llm`，默认关）

```text
B 档 753 个 span 有候选 → LLM 作答 736（98%），正确率 80.7%（我们 73.2%），净 +55
开发 95.2→95.8 · 留出 94.9→95.1 · 泛化 94.5→94.8 · 散文 74.9→76.9
```

## 指标

```text
precision = 判对 / (判对 + 判错)     ← 只在 gold 覆盖处可验证
coverage  = 判对 / gold span 总数
溢出      预测了但 gold 没覆盖 —— 不计入 precision 分母，单列
对齐差    覆盖范围不同但读音不冲突 —— 单列，不算错
```

判定方式：字符区间重叠，同一条 gold 上的多段先拼接再比读音；
规范化用 NFKC + 片假名→平假名。

`--exclude-latin` 可以剔除 gold 里含拉丁/卢恩字符的 span（205 个，不属于汉字标注范围）。

## 已知限制

```text
1. gold 是"人工选择标注"，不是全量
   散文：Aozora 编者只标难词（1.6 处/行），我们标 10 处/行 → 溢出不可验证
   歌词：Uta-Net 几乎全标（2.7 处/行），所以歌词的 metrics 是全量口径
2. 旧字旧仮名作品已过滤（只取「新字新仮名」），但仍有少量历史假名遣（云フ 之类）
3. 规则检测（tools/rules.py）是启发式的：只影响分层，不影响正确性判定
4. 散文 precision 74.9% 是"难词子集"成绩，不能当整体精度看；
   溢出抽检 60 条全对，折算整体约 91%
5. 手工集（41 条）是作者构造的，可能有主观偏差
6. 语料统计来自 NDL 青空文庫コーパス（文学域），歌词域可能有偏；
   换领域需要重建 stats 表（`make build-stats`）
7. 多音字的读音仍由引擎决定——静态手段（语料主读、搭配表、助词条件、
   词典顺序、浊点校正）全部实测负收益，剩下的错误集中在"语境决定读音"
8. 弃权换来的是覆盖率，不是精度：`emit=A` 丢 20pp 覆盖只涨 0–0.5pp
```

## 分层规则（R1–R12）
评测集按这里的规则编号分层。每条 gold 记录都带 `rules: [...]`，评测时按规则分组出指标。

> **重要**：这些标签**只用于分层和分组统计**，不参与标注判定。
> 标注器（`tools/annotate.py`）有独立的一套规则链，见`yomi.md`（docs 下） §3.3。
> 检测实现见 `tools/rules.py`，是启发式的——同一句可以命中多条，`primary` 只决定它进哪一层。

## A 组：读音本身

| ID | 规则 | 例 | 为什么难 | 检测方式（自动打标） |
|---|---|---|---|---|
| **R1** | 单一读音的普通词 | 天気→てんき、学校→がっこう | 基线，不应出错 | 不含其他规则的含汉字 span |
| **R2** | 送り仮名切分 | 食(た)べる、書(か)いた | 注音只覆盖汉字部分 | span 后面紧跟平假名 |
| **R3** | 音便（促音・連濁） | 学校→がっこう、花火→はなび | 读音与单字读音不同 | ruby 含 `っ`，或含浊音而单字读音无 |
| **R4** | 熟字訓 | 今日→きょう、大人→おとな、明日→あした／あす | 整词换读，不能按字拼 | base 命中熟字訓表 |
| **R5** | 多音词（同字異読） | 生（なま/せい/い.きる）、上手（じょうず/うわて） | 必须靠上下文 | base 命中多音词表 |
| **R6** | 数字 + 助数詞 | 一人→ひとり、二十歳→はたち、4月→しがつ | 无规律，需表 + 音便 | base 含数字/漢数字 + 助数詞 |
| **R7** | 固有名詞 | 米津玄師、渋谷、日本橋 | 读音不可推 | 启发式：span 含 ≥4 个汉字（**很粗**，会误判长熟語） |
| **R8** | 当て字・造語 | 絆→きずな、奇跡→きせき | 词典多不收录 | base 汉字数与本词 mora 数比例异常 |
| **R12** | 熟語的切分粒度 | 漢字→かんじ（整词）vs 漢(かん)字(じ)（逐字） | 影响显示与罗马音 | span 覆盖 ≥2 汉字 |

## B 组：非汉字部分（决定 C/K 与透传）

| ID | 规则 | 例 | 期望行为 |
|---|---|---|---|
| **R9** | 假名直通 | は、が、る、これ | K 级：不标，原样透传（罗马音/键位层仍可从假名派生） |
| **R10** | 片假名外来語 | パン、コーヒー、ウィンドウ | 片假名本身不需要 ruby，按 K 级透传 |
| **R11** | 拉丁/数字/符号混在 | Love、2024、！？、ー | 原样透传（K），不参与汉字判定 |

## C 组：歌词域（不另设规则编号）

歌词不复用一套 L 规则，而是**沿用上面的 R 规则 + `domain: "lyrics"` 字段**：

```text
理由   歌词的问题不是"多一类现象"，而是"同样的现象在短行、少上下文下更难"
做法   gold 记录带 domain=lyrics + title/artist，评测时按域单独出指标
分集   开发（调参）/ 留出（对外报数）/ 泛化（跨榜单检验），三者 URL 与标题零重叠
覆盖   每首曲子对每条 R 规则的命中行数，见 eval/reports/lyrics_coverage.md
```

歌词特有的观察（不作为规则，只作为解读）：

| 现象 | 对应规则 | 说明 |
|---|---|---|
| 行短、上下文缺失 | R5 多音词 | 更应 abstain |
| 当て字/詩的用法 | R8 | 与散文同策略 |
| 反復句、拟声词 | R9（假名直通） | 全假名 → K 级 |
| 英文混入 | R11 | 透传 |
| 片假名外来语多 | R10 | 歌词里比例明显高于散文 |

| S8 当て字 | R8 | 40 | 21 | 青空文庫启发式 + 手工 |

| 歌词域（开发） | R1–R11 | 30 首 | 1312 行 / 3524 span | Uta-Net 动漫榜 |

实际产出：散文 742 条（1173 span）+ 歌词开发 1312、留出 858、泛化 1139 条（共 6906 span）+ 手工 49 条。

未满额的层（R4 43/60、R5 45/80、R8 21/40、R11 13/60）：青空文庫里这类语句本身稀少，
`manual.jsonl` 补了一部分仍不够。逐层记录在 `eval/reports/manifest.json`。
散文各层的"目标"是配额上限，实际按可用语句取。

**R2（送り仮名）与 R12（熟語切分）不单设层，只作为标签记录**：
它们几乎对每句都成立，设成独立层会把别的规则的名额挤掉。

每条 gold 记录只记一个主层（`primary`），其余命中规则全部记在 `rules` 数组里；
评测时按 `primary` 分组，这样"某一层的失败"不会被其他规则的命中稀释。

## 抽样原则

```text
1. 确定性：固定 seed，同版本同结果
2. 每层独立配额，避免高频词淹没稀有规则
3. 同一句只能进一个主层（在"这句能填、且还有配额"的层里，挑缺口比例最大的；
   不是固定优先级，否则稀有层会被高频层挤光）
4. 歌词不抽样：直接取动漫榜前 N 首（换榜就换数据），
   `eval/reports/lyrics_coverage.md` 是事后统计"每首覆盖了哪些规则"，不是选择依据
```
