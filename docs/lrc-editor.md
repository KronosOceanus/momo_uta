# LRC 编辑器设计（2026-11）

> 目标：让这个工具从「练歌器」变成「能自己做歌词时间轴的工具」。
> 现状：只能读歌词、改读音；不能改文本、不能打时间轴。

## 1. 范围

```text
做
  · 在已有 LRC 上编辑（改文本、改时间戳、增删行、调整顺序）
  · 没有 LRC 的歌：手动粘贴/输入歌词，从零打时间轴
  · 点波形定位 → 点歌词行绑定时间
  · 保存回 <同名>.lrc（自动备份），另可「另存为」
  · 撤销/重做、时间戳校验

不做（这一版）
  · 多轨/多语言对齐（翻译行单独编辑）
  · 自动对齐（Whisper 强制对齐，留到以后）
  · 波形编辑（剪切、淡入淡出）—— 我们不是 DAW
```

## 2. 界面

```text
第 1 行  【开始】歌名                          振假名编辑模式 / LRC 编辑模式
第 2 行  【全选】【加行】【删行】   【保存】【另存为】【导入LRC文件】【恢复最初】
第 3 行  整体偏移 −0.5 −0.1 0.00 +0.1 +0.5                          跟随：开
第 4 行  波形（高 120px）
主区     行号 │ 时间戳 │ 文本（可编辑）        右侧罗马音在 LRC 模式隐藏
底部     上一句 / 播放 / 下一句 / 单句循环 / 重新匹配 / 速度
         自绘播放条：⟲10 ▶/⏸ 10⟳ 已播 ▬●▬ 总长 🔊
```

```text
进入编辑模式后：
  · 左栏乐谱区换成「行号 + 时间戳 + 可编辑文本」
  · 波形区出现在歌词上方
  · 双击播放/拖动等原有交互不受影响
```

## 3. 对齐交互

### 主流程（点两下）

```text
① 点击波形某处        → 出现竖直标记，读数为该处时间
② 点击某一行歌词      → 该行时间戳 = 标记时间
                        · 自动选中下一行（连续打轴）
                        · 标记保留，可连续给多行同一个时间（合唱/停顿）
③ 点已对齐的行        → 把该行时间改为当前标记（等于"覆盖"）
```

### 辅助手段

```text
空格            播放 / 暂停
Enter           给"当前选中行"打上此刻播放时间（实时打点，最快）
↑ / ↓           选中行时间 ±0.1 秒
Shift + ↑ / ↓   ±0.01 秒
Tab             跳到下一行（不打时间）
Delete          删除选中行
```

## 3.5 整体偏移（手动）

```text
用途：LRC 时间轴整体比音频快/慢几秒（换版本、剪过前奏）→ 不改文件，只挪播放对齐
控件：工具条上一行
  [−0.5s] [−0.1s]   offset: 0.00s   [+0.1s] [+0.5s]
```

```text
· 只影响「播放时的高亮/跳句」，不修改 .lrc 文件
· 每首歌单独保存（和读音修改同一套本地数据）
· 编辑器的"保存"才会真的改时间戳 —— 两种东西不要混
```

```text
区分清楚：
  整体偏移（offset） 练习用，本地数据，随时可清
  时间戳修正          真的要改 .lrc，需要保存+备份
```

## 4. 文本编辑

```text
· 每行结构：{ id, text, t }        id 稳定，排序/插入不会让时间戳错位
· 行号 = 数组序号，自动重算（用户不需要管）
· 粘贴多行 → 自动拆成多条（保留已有时间戳，新行 t = null）
· 拖拽行 → 调整顺序（时间戳跟着行走）
· 行内注音 漢字(かな) 当普通文本处理：显示原样、保存原样
  （引擎本来就认识这种写法，不会丢网易云歌词里的读音）
· 空行允许存在（间奏），保存时保留
```

## 5. 波形

### 生成

```text
ffmpeg -i <audio> -ac 1 -ar 4000 -f s16le -    → PCM 原始流
每 20ms 取 (min, max) 一对 → 5 分钟约 15000 对（约 60KB）
```

```text
缓存：data/cache/wave/<md5(绝对路径)>.json
  { "duration": 248.5, "step": 0.02, "peaks": [[min,max], ...] }
```

```text
首次生成 0.3–1 秒（ffmpeg 解码很快），之后秒开
不联网、不影响原始音频文件
```

### 用原曲还是人声？

```text
默认：人声轨（分离后）> 原曲
理由：原曲波形里间奏/鼓点/长音都像"起点"，副歌反复时几乎没法手动对齐；
      人声波形只有唱的地方有起伏，句首句尾一眼可见
```

```text
按需分离：打开编辑器时若无人声轨，显示 [分离人声] 按钮
          · 点了 → 后台跑分离（一首 4 分钟约 1–3 分钟）→ 出波形
          · 不点 → 用原曲波形，角标显示「原曲波形（对齐更费劲）」
缓存键区分来源：data/cache/wave/<md5>.<vocals|mix>.json
```

```text
代价：分离模型约 100MB（首次下载）；人声轨 flac 约 24MB/首
      → 分离是"一次离线 + 缓存"，不在播放时实时跑
```

### 渲染

```text
canvas 2D 画竖直条（每像素一列，取该列覆盖区间的 min/max）
缩放：滚轮 / 工具条 − +；范围 1–60 秒/屏
平移：按住拖动，或点时间标尺
播放头：requestAnimationFrame 跟随 au.currentTime
点击：把像素 x 映射成时间（按当前视窗换算）
```

## 6. 保存与备份

```text
实时保存（默认）
  停止编辑 1.5 秒后自动写盘，状态显示「已保存 HH:MM:SS」
  写 <stem>.lrc（和音频同目录同名）
  首次保存/导入前把原文件备份成 <stem>.lrc.bak（只做一次，不覆盖已有 .bak）
  没有 .lrc 的歌 → 新建
  保存后同时更新歌词缓存 → 播放器立刻看到新时间轴

主动保存
  点【保存】总是写一次（即使已自动保存过），提示「已保存 N 行」
  没有改动时不再提示"没有需要保存的修改"

导入LRC文件
  选外部 .lrc → 确认后直接覆盖当前歌词（覆盖前备份，若还没有 .bak）
  覆盖后重新载入表格并同步缓存

另存为
  弹保存对话框，另存到任意位置（不备份，因为是新文件）
```

```text
校验（不再弹确认框，靠界面提示）：
  · 时间戳倒退的行仍可保存，但界面上会显示出来
  · 未对齐（t 为空）的行照常保存，等以后再填
  · 总行数为 0 时拒绝保存
```

## 7. 撤销

```text
内存快照栈，最多 50 步（Cmd/Ctrl+Z 撤销，Shift 重做）
快照粒度：对齐一次、改文本一次、增删/移动一次
不做持久化（关掉就没了；文件本身是结果）
```

## 8. 服务端接口

```text
GET  /api/wave/<idx>           波形峰值（首次生成后走缓存）
POST /api/lrc/load  {idx}      取原始 .lrc 文本（没有则空）+ 是否已有文件
POST /api/lrc/save  {idx, lines:"[00:12.34] 文本" 逐行} 
                               写 .lrc + 备份 + 更新缓存
POST /api/lrc/export {idx}     返回文本让前端触发下载（或弹对话框）
```

```text
新增模块：
  nihonco_player/waveform.py   ffmpeg 解码 + 峰值 + 缓存
  nihonco_player/lrcio.py      读写 .lrc（含备份）、与缓存同步
  static/20-editor.js          编辑表格（10-app 波形 / 30-playback 时间语义）
```

## 8.5 依赖

```text
ffmpeg      波形解码（已装）
demucs      人声分离（可选，装了才能用「分离人声」）
            没有时降级为原曲波形，不影响其他功能
```

## 9. 边界情况

```text
· 音频读不出来（损坏/格式不支持）→ 波形区显示"无法生成波形"，仍可手工输入时间
· 只读目录 / 无写权限 → 保存失败时提示，并建议用「另存为」
· 已有 .lrc 来自网易云（带 [xx:xx.xx-1] 之类标记）→ 读取时保留原行，未识别行按 t 保留/丢弃给提示
· 超长音频（>30 分钟）→ 峰值仍按 20ms，文件约 360KB，可接受
· 同一首歌在多个歌单里 → 编辑的是同一个文件，存一次两边都变
· 分离失败（音频异常）→ 退回原曲波形，提示一次，不影响打轴
```

## 10. 分三步实现

```text
第 0.5 步 人声分离 + 波形来源选择（人声优先，原曲兜底）
         验证：点「分离人声」后出人声波形；没有时能用原曲波形继续
第 1 步  波形 + 播放头 + 点击定位（只读）+ 整体偏移控件
         验证：5 分钟歌波形 1 秒内出现、缩放跟手、点击时间准确、
               offset ±0.1s 立刻听感对齐
第 2 步  歌词表格编辑 + 点波形点行对齐 + 保存/备份
         验证：改一条 LRC 保存后，播放器时间轴立刻正确
第 3 步  撤销/重做、键盘打点、微调、另存为
         验证：连续打 30 行不卡、撤销正确回退
```

## 11. 已实现情况（as built，2026-11）

```text
实现位置：static/20-editor.js（编辑器 UI）、core/lrcio.py（读写）、
          core/waveform.py（波形）、http/routes.py 的 /api/lrc 与 /api/wave

与设计的差异（都已按实际需要调整）
  · 波形窗口固定 5 秒、播放头居中、跟随播放；有「跟随：开/关」开关
  · 滚轮缩放 2–10 秒（设计里写的是 2–15）
  · 波形只保留"每句起点线"（暖橙色），不再画 0.5 秒刻度与行号
  · 保存：实时保存（停手 1.5 秒）+ 主动保存（保存按钮总是写一次）
  · 备份：只保留一份 .lrc.bak（第一次保存/覆盖前生成），"恢复最初"用它
  · 新增「导入LRC文件」：选外部 .lrc 直接覆盖当前歌词（覆盖前备份）
  · 支持网易云 JSON 歌词格式（{"t":毫秒,"c":[{"tx":"..."}]}）
  · 载入时若 .lrc 行数与播放列表不一致，按播放列表对齐（避免左右错位）
  · LRC 模式下右侧罗马音隐藏，表格占满宽度
  · 未做：自动打轴、撤销之外的版本历史、行内拖动排序

键盘
  输入框内 Enter   光标处拆行
  非输入框 Enter   在选中行下面加一行
  ⌘A / Delete      全选 / 删除选中行
  ⌘Z / ⌘⇧Z         撤销 / 重做
  ⌘V（表格上）     粘贴多行，自动拆行（支持 [mm:ss.xx] 前缀）
```

## 12. 已定的三个选择

```text
① 波形高度 120px
② 默认原地保存（自动 .lrc.bak），另给「另存为」
③ 行内注音当普通文本，原样读写
④ 波形来源：人声优先（按需分离），没有则用原曲
⑤ 整体偏移：手动按钮调整（±0.1 / ±0.5 秒），只影响播放，不改文件
⑥ 不做自动打轴（Whisper / 强制对齐）—— 打轴靠手动点选
```
