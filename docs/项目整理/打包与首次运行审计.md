# 打包与首次运行审计

> 审计对象：`packaging/momo_uta.spec`、`packaging/build.sh`、现有 `dist/*`。
> 未重新构建。

## 0. 结论

```text
源码运行路径基本完整
打包产物当前不可直接作为公开分发版
```

## 1. P1：现有 dist 已落后于源码

`dist/*` 的时间戳早于最近多次修复。

如果直接分发：

```text
dist/momo-uta-base.zip
dist/momo-uta-thin.zip
dist/momo-uta-full.zip
```

用户拿到的不是当前源码版本。

`packaging/build.sh` 只做 PyInstaller：

```text
没有重新生成 zip
没有更新 VERSIONS.txt
没有 checksum
```

## 2. P1：签名与 Gatekeeper

现有 `.app` 是 ad-hoc 签名：

```text
Signature=adhoc
spctl: rejected
```

不是 Developer ID 签名，也没有 notarization。

结果：

```text
换机器下载后可能提示“已损坏”或“无法验证开发者”
```

## 3. P2：只打 arm64

`momo_uta.spec`：

```python
target_arch="arm64"
```

结果是：

```text
Apple Silicon 可用
Intel Mac 不可用
```

如果需要覆盖 Intel，需要：

```text
universal2
或分别构建并合并
```

## 4. P2：full 的 ffmpeg 路径写死

```python
ffmpeg = Path("/opt/homebrew/bin/ffmpeg")
if ffmpeg.is_file():
    binaries.append(...)
```

问题：

```text
Intel Homebrew 在 /usr/local/bin
没有 ffmpeg 时静默不打进包
full 仍会构建成功，但人声分离缺 ffmpeg
```

应在构建时显式检查并在缺失时失败，或从 PATH / 配置读取。

## 5. P2：base 与 thin 实际差异很小

两个 variant 都：

```text
exclude demucs / torch / ffmpeg
hiddenimports 包含 momo_player.core.vocals
```

区别主要是名字和 bundle id。

`base` 并没有在运行时禁用 vocals，  
如果系统里有 demucs/ffmpeg，仍可能走外部工具。

## 6. P2：VERSIONS.txt 仍是旧品牌

```text
nihonco uta
nihonco-uta-base.app
~/Library/Application Support/nihonco uta
```

与当前 `momo uta` 不一致。

## 7. 首次运行

已确认：

```text
bootstrap 创建 CURATED / CACHE / LYRICS / VOCALS / tmp
打包资源包含 config/defaults.json
包含 data/tables
包含 data/corpus/ndl_reading_stats.json
包含 data/curated 三个种子文件
static 文件齐全
```

首次运行路径本身没有发现直接崩溃点。

## 8. 构建可重复性

目前：

```text
依赖版本在 pyproject/requirements
但 build.sh 不生成 zip/checksum/版本文件
dist 产物与源码没有绑定关系
```

建议：

```text
build.sh
→ PyInstaller
→ 生成 zip
→ 生成 checksum
→ 生成 VERSIONS.txt
→ 记录 git commit
```

## 9. 建议顺序

```text
1. 重新构建 dist（否则所有修复不会进入分发包）
2. 修复 ffmpeg 查找与缺失失败
3. 决定是否支持 Intel
4. 签名/notarize（公开分发时）
5. build.sh 生成 zip/checksum/VERSIONS
6. 更新 VERSIONS.txt 品牌
```

测试基线：

```text
383 Python
68 前端
UI 冒烟通过
```
