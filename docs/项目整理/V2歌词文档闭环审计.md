> 范围：歌词读取、写入、改读音、导入、导出、备份、恢复、删除。
> 本轮只审计，不修改行为。
> 基线：303 Python、46 前端、1 项环境跳过。

## 0. 结论摘要

```text
读取闭环：基本完整
保存闭环：按“不校验、坏数据读取时丢弃”的设计
改读音闭环：基本完整
导入闭环：基本完整
导出闭环：可用，但有两条路径
备份恢复闭环：按当前策略不保留恢复前快照

```

用户决策：

```text
恢复备份不保留“恢复前”快照：不做
save_rows 不校验 rows：设计如此
  坏数据不阻断写入
  读取时丢弃无法解释的条目
trans_lang 默认值：core 改为继承旧文档
version 冲突：保留
最少行校验：保留
空文件：保留拒绝
空 rows：拒绝，且不覆盖已有文件
空歌词（只有 blank/metadata）：合法文档，允许保存
```

## 3. 待决策/风险

### 已决策：恢复备份不保留恢复前快照

```text
当前策略：恢复备份直接覆盖当前文件
不额外保存“恢复前”版本
```

```text
这是明确接受的行为，不再作为待修问题。
```

### 已决策：`save_rows` 不校验 rows

```text
nhlrc 的原则：
  写入端不校验
  读取端丢弃无法解释的条目
  歌词只是展示内容
```

```text
因此不增加 rows 结构校验。
坏数据在读取时按现有 parse 规则丢弃。
```

### 已决策：`save_rows` 的 `trans_lang` 继承旧文档

```text
core `LRC.save_rows` 的默认值改为 None
没传 trans_lang 时读取旧文档
旧文档也没有 → zh
```

```text
API 路径和直接 core 调用现在行为一致。
```

### P2：`expected_version` 可为空

`save_rows` 允许：

```text
expected_version=None
→ 直接覆盖
```

前端正常会传，但这是危险默认。

建议：

```text
API 的 save_rows 要求 version
或明确区分“新建”和“覆盖”
```

### P2：备份发生在渲染之前

`save_rows` / `import_text`：

```text
先 _backup_once
后 render / 转换
```

如果渲染抛错：

```text
备份已生成
文件没变
```

不破坏数据，但会产生无意义备份。

建议：

```text
先完成转换/校验
再备份
再写
```

## 3.1 按“软件生成 / 正规 LRC”原则的校验取舍

### 保留

```text
空文件 / 空正文
UTF-8 替换字符
导入的最少内容判断 → 改为不做“最少行数”硬限制
HTTP 必填字段 / JSON 合法性
version 冲突
锁内读写
首次备份
原子替换
读取端 seg/h/i/tid 校验与丢弃
改读音 lid/tid 目标存在
disabled / 备份语义
```

```text
默认文件来自本软件，或来自正规 LRC。
这两类输入允许较长/较短，但不允许空、乱码和坏结构。
```

### 可以删

```text
valid_import 里的 min_content_lines 硬限制
```

理由：

```text
一条有效 LRC 也可以只有一两行
正规 LRC 不应该被“行数不足”拒绝
软件生成的 nhlrc 也可能很短
```

### 不建议删

```text
空文件
空正文
UTF-8 替换字符
```

```text
它们不是“歌词质量”，而是“输入根本不是可用文本”。
```

### 空校验的边界

```text
导入：空文件 / 空正文 → 拒绝
保存：没有任何 lyric 行 → 仍拒绝
save_rows：空 rows → 拒绝
  → 不覆盖已有文件
  → blank / metadata 非空 rows 仍允许
```

### 结论

```text
保留：空、乱码、协议、版本、锁、备份、读取端丢弃
删除：最少行数硬限制
不删：空文件/空正文
```

## 3.2 本轮新增审计

### P1：legacy 导出会丢掉新增行

状态：已修复。

`rows_from_legacy` 以旧正文为骨架：

```python
skeleton = parse_v2_rows(doc.get("text") or "")
for row in skeleton:
    ...
```

它只会用 `lines` 覆盖骨架里已有的行。

如果编辑器比旧正文多出一行：

```text
旧正文 2 行
编辑器 3 行
→ 导出只保留前 2 行
```

复现结果：

```text
2 行输入 → a b
3 行输入 → a b
```

修复后：

```text
3 行输入 → a b c
```

影响：

```text
旧文档/缓存文档编辑后
导出可能丢掉新增行
```

### P2：旧 core `save` 仍默认 `trans_lang="zh"`

状态：已修复。

`save_rows` 已改为继承旧文档，但：

```python
def save(..., trans_lang: str = "zh")
```

仍然存在。

当前 `save_lyrics` 会传入 `trans_lang`，所以正常 API 路径安全；
直接调用旧 core `save` 仍可能把 en 写成 zh。

建议：

```text
和 save_rows 一样改为 None
没传时继承旧文档
```

修复后：旧 core `save` 同样继承旧文档。

### P3：备份发生在渲染/转换之前

状态：已修复。

现在统一为：

```text
读取旧文件
→ 转 rows
→ render
→ 备份
→ 原子写
```

转换失败不会再生成无意义备份。

### 两条保存入口的差异

状态：公共写入逻辑已统一。

```text
_read_original
_version_conflict
_write_v2
```

现在 `save_rows`、旧 `save`、`import_text` 共用：

```text
读旧文件
→ 版本判断
→ render
→ 备份
→ 原子写
```

仍然保留的差异只有：

```text
save_rows：直接 rows
save：body lines → rows
```

也就是“输入转换”不同，“写入事务”相同。

### 两条导出路径的差异

状态：已统一到 `LRC.export_rows`。

```text
有 rows
  → 直接使用

有 legacy lines
  → rows_from_legacy

两者都没有
  → doc.body_rows / doc.lines
```

service 不再自己判断 `kind`、不再自己选骨架。

## 3.3 第三轮审计新增

### P1：坏尾部会让读取直接抛异常

状态：已修复。

`parse_rows` 对 `lines` / `trans` 的类型没有防御：

```text
lines: 123
lines: [1]
seg: 1
trans: 123
```

会抛：

```text
TypeError: 'int' object is not iterable
AttributeError: 'int' object has no attribute 'get'
```

这违反“坏数据读取时丢弃”的原则。

修复后：

```text
尾部条目不是对象 → 丢弃
lines/trans 不是数组 → 丢弃
seg 不是数组 → 丢弃
```

不再冒泡到 API 500。

### P1：legacy 导出会保留已删除的行

状态：已修复。

`rows_from_legacy` 只追加新增行，没有截断旧骨架：

```text
旧正文 3 行
编辑器 2 行
→ 导出仍然 3 行
```

复现：

```text
3 行输入 → a b c
2 行输入 → a b
```

现在两个方向都正确：多则追加，少则截断。

### P2：`doc_from_rows` 固定 `trans_lang="zh"`

状态：已修复。

`doc_from_rows` 现在接受 `trans_lang` 并原样返回；
`lrc_action load` 传入文件的真实语言。

### P2：旧 core `save` 允许空 lines

状态：已修复。

```text
save_rows([]) → 拒绝
save([])      → 拒绝
```

不再能写空文档。

### P3：保存响应不返回服务端生成的身份

状态：已修复。

`save_rows` 现在返回：

```text
ok / path / rows / ids / backed_up / version
```

`ids` 中每项包含：

```text
i / text / lid / tokens
```

前端已有的 `mergeSavedIds` 会把这些身份合并回编辑表。
