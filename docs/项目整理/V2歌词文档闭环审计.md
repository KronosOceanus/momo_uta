## 3. 未闭环/风险

### P0：恢复备份会丢“恢复前”的当前版本

`restore_backup`：

```text
找到 bak
→ 检查 version
→ 读 bak
→ 直接 atomic_write 到当前文件
```

问题：

```text
当前文件如果是刚编辑过的新版本
恢复旧 bak 后
当前版本没有另存
```

虽然 bak 还在，但“恢复前”的状态被覆盖，用户无法在恢复后回到刚才的版本。

建议：

```text
恢复前把当前文件另存为 restore 前快照
或在恢复响应中明确告知当前版本已丢失
```

### P1：`save_rows` 不校验 rows

当前直接接受：

```text
未知 kind
重复 lid
缺失 lid
重复 tid
空 text
metadata 带换行
```

后果：

```text
坏 rows 可以写进文件
后续读取时 lid 冲突或 token 失效
```

建议：

```text
保存前做结构校验
非法输入返回 ok:false
不静默修复所有问题
```

### P1：`save_rows` 的 `trans_lang` 默认值

```python
def save_rows(..., trans_lang: str = "zh")
```

service 层会先读旧文档补 `trans_lang`，但直接调用 core 的路径默认会变成 `zh`。

建议：

```text
core 的 trans_lang 默认改为 None
由调用方或旧文档决定
不默认 zh
```

### P2：`expected_version` 可为空

`save_rows` 允许：

```text
expected_version=None
→ 直接覆盖
```

前端正常会传，但这是危险默认。

建议：

```text
API 的 save_rows 要求 version
或明确区分“新建”和“覆盖”
```

### P2：备份发生在渲染之前

`save_rows` / `import_text`：

```text
先 _backup_once
后 render / 转换
```

如果渲染抛错：

```text
备份已生成
文件没变
```

不破坏数据，但会产生无意义备份。

建议：

```text
先完成转换/校验
再备份
再写
```
