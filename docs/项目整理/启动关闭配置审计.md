# 启动 / 关闭 / 配置 / 日志审计

> 不含数据目录迁移。

## 0. 结论

```text
启动主链路可用
配置写入原子且有文件锁
发现一个会破坏用户配置的损坏恢复问题
关闭路径没有统一 flush / cleanup
```

## 1. P1：损坏的 data/config.json 会被静默覆盖

启动时：

```python
def _load(path):
    try: return json.loads(...)
    except Exception: return {}
```

损坏配置被当作空对象，直接使用默认值，没有提示。

之后用户切主题/播放模式：

```python
d = FS.read_json(FILE, {}) or {}
player = d.setdefault("player", {})
ui = player.setdefault("ui", {})
ui["theme"] = ...
```

结果：

```text
损坏的 config.json
→ 被读成 {}
→ 只写回 player.ui
→ 原文件其他配置全部丢失
```

需要：

```text
损坏时备份为 config.json.bad
提示用户
再写默认配置
```

## 2. P2：关闭应用没有统一 flush / cleanup — 已修复（最小版）

当前关闭流程：

```text
窗口关闭 → hide
应用退出 → webview.start 返回
```

没有：

```text
通知前端 flush 歌词
等待保存完成
取消语音分离任务
shutdown HTTP server
清理子进程
```

风险：

```text
未保存歌词丢失
demucs 子进程残留
后台线程在退出时被直接杀掉
```

## 3. P2：启动失败没有用户可见提示 — 已修复（最小版）

`main` 中：

```text
bootstrap
logsetup
LIB.load_cache_for_playlists
VOC.cleanup
make_server
webview.start
```

其中任何一步失败：

```text
进程退出 / 异常
用户只看到窗口没打开
```

`sys.excepthook` 只能写日志，不能提示启动失败。

已加入：

```text
main 捕获启动异常
→ stderr 打印 traceback
→ NSAlert 显示“桃歌启动失败”
→ 显示异常摘要和日志路径
→ 重新抛出，保持非零退出
```

日志初始化失败不再阻止启动，只退化为 stderr。

## 4. P2：多实例没有互斥

没有单实例锁：

```text
两个 app 进程
→ 同一个 data 目录
→ 启动时 VOC.cleanup 可能删掉另一个实例正在用的缓存
→ 配置/索引写入竞争
```

文件锁只保护单文件写入，不保护“整个应用实例”。

## 5. P3：日志初始化失败会阻止启动

`logsetup.setup()` 直接：

```text
mkdir CACHE
open app.log
```

失败时应用启动失败，没有退化到只写 stderr。

## 6. P3：日志轮转不保留历史

只保留：

```text
app.log
app.log.1
```

旧 `.1` 被覆盖。不是数据问题，但排障时可能丢上下文。

## 7. 已确认正常

```text
atomic_write_text 同目录临时文件 + fsync + replace
user_config 读写有文件锁
主题/播放模式走同一配置文件
启动时创建 frozen 用户目录
日志 Tee 到 stdout/stderr
默认配置只来自 config/defaults.json
```

## 8. 建议顺序

```text
P1 config 损坏备份与提示
P2 关闭前 flush / 任务清理
P2 启动失败弹窗
P2 单实例锁
P3 日志初始化降级
```

```text

UI 冒烟通过
```
