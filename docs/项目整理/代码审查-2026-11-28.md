## 1. P1：LRC 破坏性动作的版本保护不完整

> 状态：已修复（2026-11-28）。统一版本保护覆盖 `save` / `save_rows` /
> `import_lrc` / `restore` / `delete`。

### 位置

```text
src/momo_player/service/lrc.py
src/momo_player/core/lrc_files.py
```

### 现状

目前只有：

```text
save
save_rows
```

在 API 层强制要求已有 nhlrc 必须带 `version`：

```python
if act in ("save", "save_rows") and not req.get("version"):
    current = LRC.current_version(...)
    if current is not None:
        return conflict
```

但下面这些动作仍然可以在没有 `version` 时写入或覆盖：

```text
import_lrc
restore
delete
```

### 影响

```text
import_lrc 可以覆盖当前歌词
restore 可以覆盖当前歌词
delete 可以把当前歌词改成 disabled
```

前端正常路径大多会带版本；  
但直接调用 `/api/lrc` 或以后新增的调用方可以绕过冲突检查。

### 修复方向

统一成：

```text
任何会修改已有 nhlrc 的 action
+ version 缺失
→ 409
```

或者显式提供：

```text
force: true
```

只允许用户在明确选择“覆盖”时使用。

### 测试

```text
已有 nhlrc
import_lrc 无 version → 拒绝
restore 无 version → 拒绝
delete 无 version → 拒绝
新文档首次写入 → 允许
```

## 2. P1：AudioContext interrupted 只记录，不恢复

> 状态：已修复（2026-11-28）。`suspended` / `interrupted` 统一恢复，
> focus / visibility 时对正在播放的音频主动唤醒。

### 位置

```text
src/momo_player/static/05-audio.js
_ctxGet()
```

### 现状

当前只处理：

```js
if(this._ctx.state==='suspended')
  this._ctx.resume()
```

但 macOS WebKit 在后台、媒体焦点切换、系统音频会话变化时，  
AudioContext 可能进入：

```text
interrupted
```

而不是 `suspended`。

现有代码会记录：

```text
audio_not_running
audio_statechange
```

但不会主动恢复。

### 影响

```text
UI 仍显示播放
时间可能停住
没有声音
需要暂停/播放或拖进度条才恢复
```

这与之前用户遇到的“后台回来静音”现象一致。  
日志已经能抓到，但功能还没有修复。

### 修复方向

```text
_ctxGet / play / seek 同时处理 interrupted
window focus / visibilitychange 时检查并 resume
恢复后重新对齐播放位置
statechange 记录 before/after
```

### 测试

```text
suspended → resume
interrupted → resume
visibility 从 hidden 到 visible → 检查恢复
```

## 3. P2：metadata 去重按文本，可能丢掉合法的重复标签

### 位置

```text
src/momo_player/core/lrc_files.py
_rows_from_body()
```

### 现状

为避免 body 行和 `metadata` 参数重复写入，  
现在用文本集合去重：

```python
meta_texts = {tag["text"] for tag in metadata}

if is_metadata_text(text):
    if text.strip() not in meta_texts:
        rows.append(...)
```

### 风险

如果一首歌确实有两个相同的 metadata 标签，  
但 `metadata` 列表只包含其中一个位置，  
body 行里的另一个同名标签会被丢掉。

例如：

```text
[ar:X]
第一句
[ar:X]
第二句
```

当前策略会以 `metadata` 列表的位置为准，  
另一个同名标签可能消失。

### 修复方向

不要按文本去重，改为按：

```text
标签文本 + 预期 body 位置
```

或者明确约定：

```text
metadata 参数存在时，body 行里的 metadata 行全部忽略
```

并在文档和测试里写死。

### 测试

```text
同名 metadata 出现在两个不同位置
→ 两处都保留
```

## 5. P2：`LRC.save` 旧兼容入口仍同时接受两套行模型

### 位置

```text
src/momo_player/core/lrc_files.py
LRC.save()
```

### 现状

虽然已经删除了 `annotation_index`，  
但 `LRC.save` 仍接受：

```text
lines
annotations
translations
line_ids
token_ids
metadata
```

这些参数默认按 body 行下标解释，  
而 v2 主路径使用 rows。

### 风险

```text
以后新增调用方容易把 annotations 按 compact 行传
metadata 与 lines 同时包含 metadata 时语义不直观
```

### 修复方向

```text
所有写入先走 rows
lines/save 只保留 API 适配层
核心只接受 rows
```

目前不需要马上重构，  
但不应继续在旧入口上增加新功能。

```text

```

```text

interrupted
```
