# 歌词编辑器保存/备份/恢复审计

> 范围：保存、自动保存、flush、替换、恢复、删除、草稿状态。
> 只审计，不修改。

## 0. 结论

```text
主保存路径有锁和 revision 校验
自动保存/手动保存基本闭环
发现一个可能导致草稿丢失的替换路径
```

## 1. 正常保存

`saveLrc`：

```text
等待 SAVE_PENDING
检查 EDIRTY / force
记录 EDIT_REVISION
读取当前 EROWS
调用 /api/lrc
```

成功时：

```text
更新 LRC_VERSION
revision 未变 → merge ids + EDIRTY=false
revision 已变 → 保持 dirty
```

失败：

```text
不清除 dirty
如果非 silent 提示
```

这是正确的。

## 2. 自动保存

`markDirty`：

```text
EDIT_REVISION++
EDIRTY=true
重置 autosave timer
1.5s 后 saveLrc(true)
```

`setLrcLocked(true)` 会清理 timer，  
离开编辑器前应由 `flushLrc` 保存。

## 3. P1：replaceLrc 不检查 pending save 的结果 — 已修复

`replaceLrc`：

```js
if(NH.SAVE_PENDING) await NH.SAVE_PENDING;
const r=await NH.api(...replace/restore...);
```

如果前一次保存：

```text
返回 false
仍然存在未保存草稿
```

`replaceLrc` 仍会继续覆盖。

恢复/导入本身是显式覆盖，但这里至少应该：

```text
如果 pending save 失败
→ 不继续覆盖
→ 保留草稿
→ 提示用户重试或明确确认丢弃
```

已改为：

```text
设置 LRC_REPLACING + LRC_FLUSHING
→ 阻止切歌，但允许覆盖前的保存
→ saveBeforeReplace()
→ 失败则取消 replace
```

## 4. P2：lrcreset / 导入走同一路径

恢复和导入都调用 `replaceLrc`，因此继承上面的问题。

确认框确实提示“当前编辑内容会丢失”，  
但“保存失败”不应该等同于“用户确认覆盖”。

## 5. P2：删除歌词不检查 dirty — 已修复

`lrcfiledel` 只等待 `SAVE_PENDING`：

```js
if(NH.SAVE_PENDING && !await NH.SAVE_PENDING) ...
```

如果：

```text
EDIRTY=true
autosave timer 还没触发
SAVE_PENDING=null
```

删除会直接执行，未保存草稿丢失。

已改为：

```text
删除前同样 saveBeforeReplace()
保存失败则取消删除
```

## 6. P2：openLrcEditor 直接清 dirty — 已修复

打开编辑器后：

```js
NH.EDIRTY=false;
```

没有检查是否还有 pending save。

如果调用时存在未完成的保存：

```text
旧保存完成后 revision 可能变化
新编辑器已经加载
```

已改为：

```text
openLrcEditor 发现 EDIRTY 或 SAVE_PENDING
→ 先 flushLrc()
→ 失败直接返回
→ 不请求文档、不重建 EROWS、不清 dirty
```

`resetall` 也改为只有在 `load` 成功后才重新打开编辑器。

## 7. 已确认正常

```text
保存失败保留 dirty
版本冲突 409 保留草稿
revision 变化不误清 dirty
SAVE_PENDING 串行化
恢复/删除有版本参数
首次保存备份
切歌前 flush
```
