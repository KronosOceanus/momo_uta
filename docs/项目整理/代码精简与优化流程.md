# 代码精简与优化流程

> 状态：正式流程。
> 目标：在不加新功能的前提下，精简代码、补齐逻辑闭环、修复 bug。

## 0. 当前基线

```text
测试：303 Python，46 前端，1 项环境跳过
代码：18,848 行（src/tests/scripts/tools/packaging）
生产代码：src 10,989 行
```

```text
死代码：已完成一轮清理
剩余：公开 facade、测试辅助、PyObjC 回调参数
```

## 1. 两条主线

### A. 精简和优化代码

不改行为，只做：

```text
去重
合并重复状态
减少转发层
删除死代码
统一错误处理
减少隐式约定
降低单函数复杂度
```

### B. 代码逻辑闭环

每条链路必须回答：

```text
成功时怎样
失败时怎样
失败后保留什么
重试会怎样
取消会怎样
重启后怎样
```

## 2. 不做的事

```text
不借精简之名改产品行为
不混合“大重构 + bug 修复”
不删除没有替代方案的测试
不做没有复现的优化
不新增功能
不做数据迁移，除非单独决策
```

## 3. 单次改动流程

每次只处理一条链路或一个明确问题。

### 第 1 步：选一条链路

一次只选一个：

```text
歌词读取
歌词保存
改读音
翻译
导入
导出
备份/恢复
删除/禁用
播放切歌
缓存
```

### 第 2 步：写现状

在改动前写清楚：

```text
入口
读取了什么
写了什么
谁拥有数据
失败时发生什么
当前测试覆盖什么
```

### 第 3 步：复现问题

如果是 bug：

```text
先写失败测试
或先写可重复的手工步骤
```

没有复现，不进入修复。

### 第 4 步：找最小改动

```text
优先删代码
其次合并重复
最后才新增抽象
```

禁止：

```text
为了修一个点，顺手改三条链路
```

### 第 5 步：实施

一次提交只做一件事：

```text
一个删除批次
或一个 bug
或一个去重
```

提交信息写清楚：

```text
改了什么
为什么
怎么验证
```

### 第 6 步：验证

每组改动至少跑：

```bash
make test
```

必要时补：

```bash
.venv/bin/python -m pyflakes src
.venv/bin/python -m vulture src scripts --min-confidence 80
git diff --check
```

### 第 7 步：更新记录

```text
docs/项目整理/代码审查.md   未修的代码问题
docs/项目整理/优化.md       未做的优化
docs/项目整理/死代码清单.md 已清理/剩余
```

修完的条目直接移除，不保留过期描述。

## 4. Bug 修复流程

```text
复现
→ 写失败测试
→ 定位最小根因
→ 修复
→ 回归测试
→ 全量测试
```

Bug 记录必须包含：

```text
位置
复现步骤
期望
实际
影响
根因
修复
测试
```

## 5. 精简流程

### 5.1 可安全精简的信号

```text
无引用
只有测试引用且能迁移夹具
同功能有两个入口
同一状态有两个来源
同一错误有多种表达
多层纯转发
```

### 5.2 不能直接删的信号

```text
公开 facade
动态调用
Python 字符串调用
测试辅助
平台回调参数
```

### 5.3 精简顺序

```text
1. 无引用私有函数
2. 无引用公共函数
3. 未使用 import / 局部变量
4. 死分支 / 失效 global
5. 重复工具函数
6. 重复状态
7. 多余转发层
8. 前端死导出
```

## 6. 逻辑闭环验收

每条写链路必须满足：

```text
版本校验
锁内读改写
原子替换
失败不破坏旧文件
首次覆盖备份
错误可回传
重试可解释
```

每条读链路必须满足：

```text
文件缺失 → 明确状态
文件损坏 → 不崩溃
缓存缺失 → 可重建
网络失败 → 不阻塞本地播放
```

每条播放链路必须满足：

```text
切歌时旧请求不能覆盖新状态
音频失败不阻塞界面
歌词失败不阻塞音频
```

## 8. 每次完成的定义

一条改动算完成，必须同时满足：

```text
行为明确
失败路径明确
有回归测试
全量测试通过
无新增未定义名称
无新增死代码
文档/清单已更新
```

只满足“本机试了一下”不算完成。

## 9. 停止条件

出现以下情况，停止继续改：

```text
需要改变产品行为
需要数据迁移
需要同时改 3 条以上链路
测试无法稳定复现
修复会让旧数据不可读
```

先记录，再单独决策。
