# 曲库与导入审计

> 范围：导入、配对、曲库索引、指纹、歌单、缺失与重建。
> 本轮只审计，不修改行为。
> 基线：303 Python、46 前端、1 项环境跳过。

## 0. 结论

```text
UID 身份：闭环
按歌单懒加载：闭环
全量扫描/裁剪索引：闭环
缺失保留：基本闭环
导入音频：闭环
导入音频 + LRC：基本闭环
外部文件被替换/重打标：不完整
异常导入的反馈：不完整
```

## 5. 发现的问题

### P1：索引路径对应到另一个 uid 时会静默丢歌

状态：已修复。

`load_for_playlists` 现在校验 `_entry` 返回的 uid；不匹配就跳过并重新计算 missing。

`load_for_playlists` 先按 uid 选路径：

```python
chosen[uid] = p
```

后面：

```python
e = _entry(p, ...)
if e and e["file"] not in seen:
    out.append(e)
```

没有检查：

```text
e["uid"] == uid
```

如果文件被替换、重打标签，指纹从 uid A 变成 uid B：

```text
索引仍给 uid A → 路径 p
_entry(p) 返回 uid B
out 里加入了 uid B
missing = wanted - set(chosen) 仍为空
```

结果：

```text
播放列表引用 A
实际曲库只有 B
A 被视为“没有缺失”
```

这会让一首歌悄悄从歌单里消失，且不触发缺失提示。

建议：

```text
按 uid 取路径后，必须校验 _entry 返回的 uid
不匹配 → 记入 missing，触发重建
```

### P2：LRC 配对可能误配

`_stem_key` 会去掉：

```text
数字前缀
符号
部分括号后缀
```

如果同目录有：

```text
01 Song.mp3
Song.mp3
Song.lrc
```

可能把同一个 LRC 配给错误的音频。

同目录“唯一 LRC”兜底也会在没有同名匹配时配对唯一 LRC。

建议审计或增加：

```text
文件名完全匹配优先
归一化匹配只作为次选
同目录唯一 LRC 增加确认/记录
```

### P2：异常导入可能没有反馈

`import_paths` 中：

```text
valid_import 通过
LRC.import_text 返回 ok:false
```

音频既没有进入 `added`，也没有进入 `pending`，只表现为少了一首。

建议：

```text
返回 failed 列表
或把导入失败的音频放进 pending 并记录原因
```

### P2：歌单 JSON 坏结构可能崩溃

`playlists.load`：

```python
out["lists"] = [x for x in d.get("lists", []) if x.get("id") and x.get("name")]
out["members"] = {k: list(v) for k, v in d.get("members", {}).items()}
```

如果 `lists` 里不是对象，或 `members` 里不是数组：

```text
AttributeError / TypeError
```

这是“坏数据直接丢弃”原则之外的情况。

### P2：导入后加入歌单和加入曲库不是原子操作

`import_to_list`：

```text
LIB.add_paths()
PL.add(lid, uids)
```

`uids` 来自 `res["added"]`，不是来自 `add_paths` 的结果。

如果文件在两步之间消失，或 `add_paths` 拒绝：

```text
歌单新增了 uid
曲库没有对应条目
```

会留下一个立即缺失的歌单成员。

### P3：删除/移动文件后索引不会立刻裁剪

`paths_by_uid` / `library_index` 仍保留旧路径，直到：

```text
下次全量扫描
或 rebuild_library()
```

`load_for_playlists` 只在用到时过滤 `p.is_file()`，不会主动 prune。

这是缓存延迟，不是数据丢失，但会影响缺失提示的及时性。

### P3：重复音频清理后 imports.json 仍可能保留旧路径

清理重复音频只移动文件，不改：

```text
data/curated/imports.json
```

旧路径仍留在导入历史里，`load_imports` 会跳过不存在文件，但记录不会自动清理。

## 6. 已确认闭环

```text
移动/改名音频：uid 不变
同内容副本：uid 相同
LRC 导入：写 nhlrc
nhlrc 优先于 LRC
无 LRC 音频：pending
缺失 UID：保留在歌单
全量重建：裁剪失效索引
```

## 7. 测试缺口

```text
索引路径指向 uid B
音频被替换但路径不变
LRC 配对误配
import_text 失败
导入后 add_paths 失败
playlists.json 坏结构
删除文件后的 missing 提示
imports.json 旧路径
```

## 8. 建议顺序

```text
1. ✅ load_for_playlists 校验 _entry uid
2. 导入失败返回 failed / pending
3. 歌单 JSON 坏结构丢弃
4. 导入后加入曲库和歌单保持一致
5. LRC 配对规则审计
6. 索引延迟裁剪
```

前两项优先，因为它们会造成“歌悄悄消失”。
