# Swift 原生音频审计

> 日期：2026-11-29  
> 分支：`feature/native-audio`  
> 审计基线：`bf1d35e`  
> 状态：POC 审计，未修改代码

## 1. 审计结论

Swift 原生音频的最小链路已经成立：

```text
Swift helper 编译
IPC load/play/pause/seek/status/volume
WAV / MP3 / 不同采样率切换
Python /api/native_audio
前端 NativeAudioEngine
打包进 Contents/Helpers
ad-hoc 签名
应用启动并加载 helper
```

但当前仍是 POC，不建议：

```text
合并 main
默认对所有用户开启 native_audio
```

原因：

```text
切歌竞态
失败处理不完整
时间基准不是音频时钟
helper 的 deployment target 与 app 不一致
缺少真实集成测试
```

## 2. 当前音频结构


## 4. P1 问题

### 4.1 切歌/暂停竞态

位置：

```text
src/momo_player/static/04-native-audio.js
```

现状：

```text
src 变更只重置字段
没有 loadSeq / playSeq
```

风险：

```text
快速切歌
播放中暂停
连续 seek
```

可能出现：

```text
旧请求在新歌上执行
暂停后又被旧 play 启动
A 歌响应覆盖 B 歌 duration
seek 响应覆盖新歌时间
```

对比：

```text
WebAudio AudioEngine 已有 _loadSeq / _playSeq
NativeAudioEngine 没有
```

解决方案：

```text
1. 增加 _loadSeq / _playSeq
2. load 捕获当前 seq 和 url
3. 响应回来时校验 seq / url
4. play 捕获 seq，await 后再次校验
5. src 变更时使旧 play 失效
```

验收：

```text
快速连续切三首歌
最终只播放最后一首
暂停后不会被旧请求重新播放
```

### 4.2 helper 失败处理不完整

位置：

```text
src/momo_player/static/04-native-audio.js
src/momo_player/service/native_audio.py
```

现状：

```text
preload 失败
→ commitAudio 的 catch
→ fallbackToOriginal
→ 仍然设置 native src
→ 还是调用 native
```

结果可能是：

```text
没有声音
没有 toast
播放状态不明确
```

明确原则：

```text
native 分支不回退 WebAudio
不混两套播放引擎
```

正确策略：

```text
helper 不存在
→ 明确报错，不播放

helper 崩溃
→ 重启 helper
→ 重新 load 当前歌曲
→ seek 到上次时间
→ 恢复播放

重试失败
→ 前端提示“原生音频不可用”
```

不建议：

```text
静默切换到 WebAudio
```

原因：

```text
时间基准不同
状态机不同
调试困难
与“切到 Swift”目标冲突
```

验收：

```text
删除 helper
→ 有明确错误提示

kill helper
→ 应用能重启 helper 并恢复当前歌曲
```

### 4.3 时间基准不是音频时钟

位置：

```text
native/momo-audio/main.swift
```

现状：

```text
play 时记录 Date
current = position + Date.now - playDate
```

问题：

```text
系统睡眠
引擎启动延迟
输出设备切换
```

可能导致：

```text
歌词与音频漂移
波形播放头与真实声音不一致
```

解决方案：

```text
playerNode.lastRenderTime
→ playerTime(forNodeTime:)
→ sampleTime / sampleRate
```

时间应以音频节点为准，  
Date 只作为无法取得 render time 时的兜底。

验收：

```text
播放 20 分钟
歌词仍与音频同步
暂停/恢复后时间不跳
系统睡眠后时间不跳
```

### 4.4 helper deployment target 不一致

位置：

```text
native/momo-audio/build.sh
packaging/momo_uta.spec
```

现状：

```text
helper: minos 27.2
app: LSMinimumSystemVersion 12.0
```

后果：

```text
macOS 12～26
→ app 能启动
→ helper 启动失败
→ 原生音频不可用
```

解决方案：

```text
swiftc 指定 -target arm64-apple-macos12.0
```

或者：

```text
明确只支持 macOS 27
→ 同步修改 app 的 LSMinimumSystemVersion
```

当前建议：

```text
保持 app 最低 12
→ helper 也编译到 12
```

影响：

```text
当前 macOS 27 行为不变
旧 macOS 可用
如果未来使用新 API，需要 availability 判断
```

验收：

```bash
vtool -show-build dist/native/momo-audio
```

应看到：

```text
minos 12.x
```

## 5. P2 问题

### 5.1 播放条仍然 10Hz

现状：

```text
currentTime getter 有插值
波形每帧读取
```

但：

```text
paintTransport 只在 timeupdate 更新
timeupdate 由 100ms status 轮询触发
```

表现：

```text
波形播放头顺
进度条和时间数字仍然一格一格跳
```

解决方案：

```text
播放时用 requestAnimationFrame 调 paintTransport
不要增加 HTTP 轮询频率
```

验收：

```text
播放条、时间数字、波形播放头都连续
暂停后停止 rAF
```

### 5.2 native 生命周期日志误报

位置：

```text
src/momo_player/static/05-audio.js
```

现状：

```text
NativeAudioEngine 没有 _ctx
audioLifecycle 读到 state = none
```

结果：

```text
每次可见性变化都可能写日志
但这不是音频异常
```

解决方案：

```text
native 分支显式标记引擎类型
或 audioLifecycle 在 native 下跳过 WebAudio 状态判断
```

### 5.3 Swift 状态数据竞争

位置：

```text
native/momo-audio/main.swift
```

共享状态：

```text
playing
ended
position
anchor
scheduleToken
```

访问方：

```text
主线程：处理 stdin 命令、读取 status
音频线程：AVAudioPlayerNode completion handler 写入状态
```

竞争例子：

```text
主线程读 playing=true、ended=false
音频线程同时写 playing=false、ended=true、position=duration
```

可能返回不一致快照：

```text
playing=true
ended=false
current=duration
```

另一个例子：

```text
主线程 seek 增加 scheduleToken
旧 completion 同时检查 token
```

解决方案：

```text
1. 所有状态读写走同一个串行队列
2. 或使用 NSLock 保护快照
3. completion 只投递事件，不直接改共享状态
```

验收：

```text
连续 seek
播放自然结束
暂停/恢复
不出现 ended 与 playing 矛盾
```

### 5.4 IPC 协议不完整

现状：

```text
Python 发送 id
Swift 忽略 id
Swift 响应不返回 id
```

当前串行调用没问题，  
但不利于：

```text
超时定位
错配排查
多请求扩展
```

解决方案：

```text
Swift 原样回传 id
Python 校验响应 id
```

### 5.5 helper 诊断被丢弃

现状：

```text
stderr=subprocess.DEVNULL
```

后果：

```text
AVAudioEngine 启动失败
文件解码失败
helper 崩溃
```

Python 侧看不到原因。

解决方案：

```text
stderr 写入日志文件
或通过独立诊断通道输出
```

### 5.6 原生能力尚未迁移

当前仍缺：

```text
rate
pitch
单句循环
vocals 播放轨
```

这是 POC 范围，不是回归。  
但需要明确：

```text
SoundTouch 仍由 Python 生成
前端仍通过 URL 切源
```

## 6. P3 问题

### 6.1 任意路径问题

位置：

```text
src/momo_player/service/native_audio.py
```

`_resolve` 实际接受任意本地路径，  
和注释“只接受 /audio”不一致。

当前是本地应用，风险有限，  
但应限制为：

```text
/audio/<uid>
SoundTouch 缓存路径
库内文件
```

### 6.2 GET 路由未使用

```text
GET /api/native_audio
```

目前前端使用 POST status，  
GET 可以保留为诊断，也可以移除。

### 6.3 Swift deprecated API

macOS 27 编译出现：

```text
AVAudioPlayerNode.play()
AVAudioEngine.connect
```

警告。  
不影响当前运行，后续应迁移到新 API。

### 6.4 清理不完整

```text
helper 退出时没有显式 engine.stop()
没有崩溃后自动重建
没有后台 30 分钟测试记录
```
