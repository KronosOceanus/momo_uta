# 歌词练习播放器

> 2026-11 整理版。代码在 `nihonco_player/`，标注能力全部来自 `nihonco_yomi/`。

## 1. 是什么

本地音频 + 带时间戳的歌词 + 振假名的**逐句练习播放器**。

```bash
make app          # 桌面窗口（唯一入口）
```

```text
音乐放哪    ~/Music/网易云音乐（mp3 / flac / wav）
歌词哪来    data/cache/lyrics/*.json（tools 离线抓：网易云 + MusicBrainz 规范化）
振假名哪来  nihonco_yomi.Annotator
```

**启动只读缓存，不联网**（约 12 秒）。

## 1.5 三个数字：文件 / 库 / 列表

| 名称 | 现在是多少 | 含义 |
|---|---|---|
| **文件** | 995 | 音乐目录里所有音频文件 |
| 疑似有人声 | 441 | 文件名像歌手-歌名的（排除伴奏标注等） |
| **库** | **340** | 抓到歌词的（缓存有 LRC 且内容行 ≥3）→ `scan_library()` 的结果 |
| **列表** | **226** | 界面上实际显示的 = 库 − 标了 ♪(58) − 标了 语(56) |

```text
库      磁盘 + 缓存层面的事实：这些歌确实有歌词，能练
列表    视图：按人工标记过滤后"应该练"的那些
```

```text
226 = 340 − 58(纯音乐) − 56(非日语)
```

列表过滤由配置控制：

```json
{"player": {"show_hidden": false}}     // false = 过滤 ♪/语（默认）
```

```text
设置 true → 列表回到 340 首，标记仍显示在列表项右侧，只是不再隐藏
```

## 3. 交互约定（别改错）

```text
列表     单击载入（不打断播放）｜双击载入并播放｜▶ 只标"正在播放"的那首
播放     点歌词/上一句/下一句 → 保持当前播放状态
按钮文案 由 au.paused 驱动（切歌、播完都会同步）
循环     以"上一帧高亮句"为基准，跨过下一句起点才回跳（不截尾音）
看别的歌 不跟随当前音频滚动（PLAYING !== 当前显示时直接 return）
```

## 4. 歌词显示规则

| 类型 | 判定 | 显示 |
|---|---|---|
| 日语行 | 含假名 | 振假名 + 档位色（A 绿 / AB 琥珀 / B 灰 / C 淡） |
| 行内注音 | `漢字(かな)` | 用 LRC 给的读音（**已知：一词多注音会错位，不再处理**） |
| 外语行 | 整行无假名 | 原样，不注音 |
| 元数据行 | 作词/作曲/编曲/制作 | 原样（当前也会被注音，未特殊处理） |

## 5. 编辑

```text
普通模式    B 档有候选 → 点开列表改（无候选不可点）
编辑模式    A / AB / B 都可点 → 输入框手输（只收 ぁ-んー）
重置        「全部重置」清掉当前歌的所有本地修改
存储        localStorage: uta:<文件名md5> → {"行:起点": "读音"}
IME         输入法组词中的回车不触发确定（isComposing / keyCode 229）
```

## 6. 标签（人工）

```text
列表每行右侧：♪ 纯音乐 · 语 非日语 · ✗ 配错
存 data/curated/song_tags.json
inst / nonja 的歌不进列表（文件与缓存都不动）
```

## 7. 接口

```text
GET  /                    页面
GET  /api/library         歌单（过滤 inst/nonja）
GET  /api/song/<idx>      {idx,key,title,artist,lines[],audio}
GET  /audio/<idx>         音频（支持 Range）
POST /api/line            {idx,line,start,reading}      改一处
POST /api/apply           {edits:[...]}                 批量恢复
POST /api/rematch         {action,idx,duration}         候选 + 分数
POST /api/pick            {action,idx,id}               选定并覆写缓存
POST /api/tag             {action,key,tag}              打标/取消
```


## 9. 已知问题

```text
① 行内注音 `人(ひと)は迷(まよ)い` 多注音挤进一个词会错位（明确不修）
② 匹配：小众/翻唱/剪切版仍会落空；靠「重新匹配」手工挑
③ 歌词覆盖面：部分 LRC 只到半首（标题后提示 ⚠）
④ 前端未组件化：状态全是全局变量，删改 DOM 容易留死引用
⑤ 前端没有自动化测试
```

## 附录：一次人工标注的结论（2026-11）
数据：`data/curated/song_tags.json`（592 首，用户手动标）
口径：按歌曲 key（文件名 md5）标记，通过 `/api/song` 回查特征

## 计数

```text
纯音乐 inst     500
非日语 nonja     66
配错   wrong     26
（三者互斥，没有一首打了两个标）
```

## 特征对照（歌词层面）

| 标签 | n | 假名占比 ≥10% | 假名 ≈0% | 歌词行数中位 |
|---|---|---|---|---|
| inst | 500 | 4% | 96% | 2 |
| nonja | 66 | 8% | 89% | 42 |
| wrong | 25 | 40% | 60% | 13 |

## 结论

```text
① 纯音乐：96% 歌词假名为 0、行数中位 2
   → 可以自动识别：行数 ≤ 3 或 假名占比 < 1% 且行数很少

② 非日语：89% 假名为 0，但行数中位 42（有完整歌词）
   → 自动判据：假名占比 < 1% 且行数 > 10

③ 配错：假名占比两极分化（40% 有日语、60% 全无）
   → 单纯语言判据抓不全；需要"歌名对不上"或时长对不上
   → 40% 那批是"配到了另一首日文歌"，语言判据无能为力
```
