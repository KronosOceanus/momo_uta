# 歌词数据模型设计

> 状态：设计提案，尚未实现。
> 目标：消除 `body_rows` / `compact lines` 两套行空间。
> 文件版本：只支持 `v: 2`；不读取、不迁移旧文件。
>
> 实现状态：第 1 步 `core/lyric_rows.py` 已落地；v2 的 core `load_rows` / `save_rows` 也已接入；
> `service/lyric_document.py` 和 `/api/lrc load_rows / save_rows` 已接入；
> v2 改读音入口 `edit_reading` 与播放派生 `playback` 已接入；
> core 的 split_row / merge_rows 也已落地；
> LRC 编辑器与普通播放载荷已能使用 v2 rows；无 v2 尾部的旧文档仍保留临时回退。

## 0. 一句话

```text
只有一份 rows
每行有稳定 row.id
lyric 行有 lid
token 有 tid
播放视图从 rows 派生
```

```text
compact 不是第二份权威数据
它只是播放视图。
```

## 1. 当前问题

现在同时存在：

```text
body_rows
  编辑器/文件顺序
  包含空行、metadata、草稿行

compact lines
  播放/注音/翻译顺序
  不包含空行和 metadata
```

由此产生：

```text
annotation i      相对 compact
trans i           相对 compact
lid/tid           相对 compact
metadata.before   相对 compact
编辑器 EROWS      相对 body
```

任何跨边界代码都必须做行号转换。漏一次就是：

```text
读音错行
翻译错行
metadata 插错位置
lid/tid 丢失
空行导致整体偏移
```

这是模型问题，不是单点 bug。

## 2. 设计原则

```text
1. 行只存在一份
2. 行身份不依赖位置
3. 空行只是行，不是索引偏移
4. 播放行是派生结果，不是第二份数据
5. 持久化数据按身份关联，不按第几行关联
```

## 3. 核心模型

### 3.1 Row

```ts
type Row = {
  id: string;              // 编辑器行身份
  kind: "lyric" | "blank" | "metadata";
  text: string;            // lyric 正文 / metadata 原始行 / blank ""
  t: number | null;        // lyric 时间戳；blank 可保留时间戳
  lid: string | null;      // lyric 行身份
  tokens: Token[];         // lyric 的 token
  trans: string;           // lyric 译文
}
```

```ts
type Token = {
  tid: string;
  start: number;           // UTF-16 code units
  end: number;             // UTF-16 code units
  base: string;
  ruby: string | null;
  level: string | null;
}
```

规则：

```text
kind=lyric
  → 有 lid/t/tokens/trans
  → 参与播放、注音、翻译

kind=blank
  → text=""
  → t 可以保留时间戳，但不参与播放
  → 不占标注意义上的行

kind=metadata
  → text 是原始 [ar:] / [ti:] / [offset:] 行
  → 不参与播放、注音、翻译
```

### 3.2 播放视图

```ts
playable = rows
  .filter(r => r.kind === "lyric" && r.t !== null)
  .sort((a,b) => a.t - b.t || a.bodyIndex - b.bodyIndex)
```

```text
playable 的时间顺序只用于播放/高亮
编辑器仍然按文件顺序显示 rows
```

### 3.3 为什么 metadata 也是 row

现在 metadata 用：

```text
before: compact 行号
```

空行一插就错位。

改成：

```text
metadata 自己就是 rows 中的一行
```

保存时按 rows 顺序直接输出，不需要 before 映射。

## 4. nhlrc 存储

### 4.1 版本

```text
v: 2
```

```text
不读取 v1
不生成 legacy id
不迁移旧 nhlrc
不维护旧读取器兼容
```

### 4.2 正文与 `i`

正文仍按 rows 顺序写。

尾部 `i` 是 **body 行号**，不是 compact 行号：

```text
i = rows 中的位置，包含 blank / metadata
```

它只负责把尾部条目锚回具体正文行。

真正身份仍然是：

```text
lid / tid
```

示例：

```lrc
[ar:歌手]
[00:01.00]君

[00:02.00]
[00:03.00]花

```

对应：

```text
row 0 = metadata  [ar:歌手]
row 1 = lyric     君
row 2 = blank
row 3 = blank     带时间戳
row 4 = lyric     花
row 5 = blank     尾部空行
```

尾部：

```json
{
  "v": 2,
  "lines": [
    {
      "i": 1,
      "lid": "l_aaa",
      "h": "1234abcd",
      "seg": [["君", "きみ", "A"]],
      "tid": ["t_aaa"]
    },
    {
      "i": 4,
      "lid": "l_bbb",
      "h": "abcd1234",
      "seg": [["花", "はな", "A"]],
      "tid": ["t_bbb"]
    }
  ],
  "trans_lang": "zh",
  "trans": [
    {"i": 1, "lid": "l_aaa", "h": "1234abcd", "text": "你"},
    {"i": 4, "lid": "l_bbb", "h": "abcd1234", "text": "花"}
  ]
}
```

### 4.3 `i` 和 `lid` 的职责

```text
i    正文锚点，只用于读取时把 lid 挂到 row
lid  行身份，跨应用内插入/删除/移动保持
h    文本校验，不是身份
```

### 4.4 有译文、无 token 的行

每一条 lyric 都必须写 `lines` 条目，即使没有 seg/tid：

```json
{
  "v": 2,
  "lines": [
    {
      "i": 1,
      "lid": "l_aaa",
      "h": "1234abcd",
      "seg": [],
      "tid": []
    }
  ],
  "trans_lang": "zh",
  "trans": [
    {"i": 1, "lid": "l_aaa", "h": "1234abcd", "text": "你"}
  ]
}
```

这样：

```text
有译文、没有读音/token 时
  → lid 仍然存在
  → trans 仍然能按 lid 关联
```

## 5. 加载

### 5.1 只读 v2

```text
v != 2
  → 拒绝读取
  → 不迁移
  → 不生成 legacy id
```

### 5.2 正文 → rows

```text
解析正文每一行
  → lyric / blank / metadata
  → 保留原始顺序、尾部空行、带时间戳空行
```

### 5.3 lines / trans → lid

```text
lines[i]：
  → 校验 i 在 rows 范围内
  → 校验该 row 是 lyric
  → 校验 h 与正文一致
  → 把 lid 挂到 row

trans[i]：
  → 同样校验 i / lid / h
  → 按 lid 挂译文
```

```text
lid 找不到 → 丢弃该条
lid 重复   → 丢弃后出现的条目
i/h 对不上 → 丢弃该条
```

### 5.4 外部编辑的限制

如果用户在外部编辑器里交换两行同文歌词：

```text
正文顺序变了
尾部 i 没有变
  → 文本哈希对不上
  → 该条按无效处理
```

这是明确限制：

```text
应用内重排：lid 保持身份
外部重排：不保证恢复身份
```

## 6. 保存

```text
POST /api/lrc save
{
  "rows": [...],
  "version": "..."
}
```

后端：

```text
1. 校验 rows 顺序、row.id、lid
2. lyric rows 按 lid 找原 row
3. 未改 token 保留 tid/ruby/level
4. 新 token 重新注音并分配 tid
5. metadata / blank 原样写正文
6. lines / trans 按 body i + lid 写尾部
7. 每条 lyric 都写 lines 条目，允许 seg/tid 为空
```

不再需要：

```text
body_to_lyric
annotation_index
_map_new_to_old
metadata.before 映射
```

保存契约必须保留：

```text
version 冲突检查
原子写入
disabled
trans_lang
```

## 7. 编辑器

`EROWS` 就是 rows。

```text
输入正文
  → 更新 lyric row
  → 重新计算 token span

加空行
  → rows.splice(pos, 0, blank row)
  → 不影响任何 lid

删除行
  → rows.splice
  → 其他行不变

拆行
  → 原 row 保留 id/lid
  → 新 row 新 id
  → 完整 token 迁移

合并行
  → 保留内容主体 row 的 id/lid
  → 另一行 token 合并

metadata
  → kind=metadata
  → 原样显示/保存
```

`lrcText()`：

```text
rows.map(row => serialized line)
```

不再单独维护：

```text
LRC_METADATA
body_rows
```

### 7.1 正文往返

必须保留：

```text
尾部空行
带时间戳的空行
metadata 的相对顺序
```

`_split_nhlrc` 不能再用 `.rstrip()` 直接吃掉正文尾部空行。

## 8. 行操作规则

| 操作 | row.id | lid | tokens | trans |
|---|---|---|---|---|
| 普通改正文 | 保留 | 保留 | 未改 token 保留 | 保留 |
| 改时间 | 保留 | 保留 | 保留 | 保留 |
| 改翻译 | 保留 | 保留 | 保留 | 更新 |
| 上下移动 | 保留 | 保留 | 保留 | 保留 |
| 插入空行 | 新 | 无 | 无 | 无 |
| 删除空行 | 删除 | 无 | 无 | 无 |
| 插入歌词 | 新 | 新 | 新 | 空 |
| 删除歌词 | 删除 | 删除 | 删除 | 删除 |
| lyric → blank | 保留 row.id | 清除 lid | 清除 tokens | 清除 trans |
| blank → lyric | 保留 row.id | 新 lid | 重新注音 | 空 |
| 拆行 | 原侧保留 | 内容主体侧保留 | 完整 token 迁移 | 跟随保留 lid 的一侧 |
| 合并 | 目标保留 | 内容主体侧保留 | 完整 token 合并 | 按正文顺序拼接非空译文 |

拆行规则具体化：

```text
左半非空 → 左半保留原 lid
左半为空 → 右半保留原 lid
新出现的一侧新 lid
译文跟随保留原 lid 的一侧
另一侧译文为空
```

合并规则具体化：

```text
左半非空 → 合并后保留左 row.id/lid
左半为空 → 合并后保留右 row.id/lid
译文按正文顺序拼接，空译文跳过
```

## 9. Token 计量单位

```text
token.start / token.end
  = UTF-16 code units
```

原因：

```text
前端 input.selectionStart / JS string slice 都是 UTF-16
```

后端不能直接用 Python 字符串下标切片，必须：

```text
UTF-16 offset → Python code point offset
```

```text
base 校验必须在转换后的真实子串上做
```

nhlrc 只存 `seg / tid`，不存 `start/end`；span 是 API/编辑器字段。

## 10. 改读音接口

旧接口：

```text
line + start
```

新接口必须用身份：

```json
{
  "uid": "...",
  "lid": "l_aaa",
  "tid": "t_aaa",
  "reading": "きみ",
  "version": "..."
}
```

规则：

```text
按 lid 找 row
按 tid 找 token
只改该 token
version 不匹配 → 409
token/row 不存在 → 拒绝，不按 line/start 猜
```

## 11. 播放视图与高亮

派生：

```text
playable = lyric rows with t != null
按 t 升序
同一 t 按文档顺序
```

规则：

```text
播放/上一句/下一句/单句循环都基于 playable
编辑器仍按文件顺序显示
```

高亮：

```text
取 playable 中最后一个 t <= currentTime 的行
同一时间戳按文档顺序决定
```

如果时间戳在文件里乱序：

```text
播放按时间排序
编辑器不重排
```

## 12. 不兼容旧文件

```text
不读取 v1
不生成 legacy lid
不迁移旧 nhlrc
不维护旧前端兼容
```

新代码只接受：

```text
v2 + lid
```

## 15. 风险

```text
这是结构性重构，不是小修
会同时改 core/service/API/前端/测试
metadata 的 UI 呈现需要决定
UTF-16 / Unicode 转换需要测试
```

但继续维护两套行空间，风险更大：

```text
每加一个功能都要再写一次 index 映射
每漏一次就是一类错行 bug
```

## 16. 结论

```text
采用：单一 rows + 稳定 lid/tid + 派生播放视图
停止：body_rows / compact 双权威 + 到处 annotation_index
```

这是比继续打补丁更小的长期成本。
