## 1. 导入时 .nhlrc 无效不会回退到 .lrc

- 优先级：高
- 状态：⬜ 待修
- 位置：`core/importing.py`

### 现状

`_pick()`：

```text
.nhlrc 优先
其次较新的
```

然后只校验选中的一个：

```python
lrc = _pick(cand)
raw = lrc.read_text(...)
ok, _why = LRC.valid_import(raw)
if not ok:
    pending.append(str(a))
    added.append(str(a))
    continue
```

如果目录里同时有：

```text
歌曲.nhlrc   ← 损坏/不合法
歌曲.lrc     ← 合法
```

会选中 nhlrc，校验失败，然后直接放弃；不会尝试 lrc。

### 影响

```text
音频进入待匹配
明明有可用 LRC 却没用
```

### 修复方向

```text
按候选顺序逐个校验
第一个 valid_import 通过的才使用
```

## 2. 导入音乐+LRC 的覆盖计数不完整

- 优先级：中
- 状态：⬜ 待修
- 位置：`core/importing.py`
- 已记录：BUG-001

### 现状

音频 + LRC 主配对路径：

```python
LRC.import_text(str(a), raw, ...)
```

没有检查 `LRC.exists(a)`，也没有累加 `overwritten`。

### 影响

```text
已有 nhlrc 被覆盖
前端提示只显示“新增 N 首”
不显示“覆盖 N 首”
```

### 修复方向

```text
写 nhlrc 前检查 LRC.exists(a)
  → 计入 overwritten
```

## 3. 导入路径重复时统计可能偏大

- 优先级：中
- 状态：⬜ 待修
- 位置：`core/importing.py`
- 已记录：BUG-002

### 现状

用户同时选：

```text
audio.mp3
audio.mp3 所在目录
```

`audios` 会包含同一个文件两次。

下游：

```text
LIB.add_paths 按 file 去重
PL.add 按 uid 去重
```

但：

```text
added / pending / overwritten
```

统计可能重复。

### 修复方向

```text
收集阶段按 resolve() 去重
```

## 4. `_metadata_for_body` 跨层私有调用

- 优先级：中
- 状态：⬜ 待修
- 位置：`service/lrc.py`

### 现状

```python
LRC._metadata_for_body(...)
```

service 直接调用 core 的私有函数。

功能没问题，但边界不干净：

```text
service 不应该依赖 core 私有实现
```

### 修复方向

```text
core 暴露 metadata_for_body
或
把映射封装进 render_nhlrc
```

## 5. `LRC.save` 的 annotations 索引契约仍隐式

- 优先级：中
- 状态：⬜ 待修
- 位置：`core/lrc_files.py`、`service/song.py`

### 现状

`LRC.save` 现在会自动计算：

```text
body 行 → annotation 行
```

但 `annotations` 本身仍依赖调用方传：

```text
body-keyed
```

当前 service 是对的，但内部 API 仍有一个隐含约定：

```text
LRC.save(lines=body_rows, annotations=compact_keyed)
  → 可能写歪
```

### 修复方向

```text
显式接收 body_rows + lyric_rows
或
在 LRC.save 内部统一转换 annotations
```

## 6. 只导入音乐时，目录里的 LRC 不统计

- 优先级：低
- 状态：⬜ 待修
- 位置：`core/importing.py`

### 现状

`with_lrc=False` 时：

```text
显式选中的 .lrc
  → rejected_lrc

目录里的 .lrc
  → 不扫描
  → 不提示
```

用户选了一个包含大量 LRC 的目录时，只会看到：

```text
新增 N 首
```

不会知道目录里的歌词被忽略。

### 说明

这可能是预期语义，不一定修。

需要确认：

```text
只导入音乐
  → 目录里的 LRC 是“明确忽略”
  → 还是“提示后忽略”
```

## 建议修复顺序

```text
1. nhlrc 无效时回退 lrc
2. 覆盖计数
3. 路径去重
4. metadata 私有调用
5. LRC.save 的 annotations 契约
6. 目录 LRC 提示
```
